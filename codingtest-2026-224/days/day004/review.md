# Day 4 Review — 인덱스 범위 실수 정리

## 오늘 틀리기 쉬운 부분

- [ ] Python List의 첫 인덱스는 0이다.
- [ ] 길이가 N이면 마지막 인덱스는 N - 1이다.
- [ ] `numbers[N]`은 마지막 원소가 아니다.
- [ ] `i + 1`을 사용할 때 i가 마지막 인덱스까지 가지 않게 했다.
- [ ] 합계 변수는 반복문 밖에서 한 번만 초기화했다.
- [ ] 최댓값 초기값을 무조건 0으로 두지 않았다.
- [ ] 최솟값 초기값을 임의의 큰 숫자로 두기 전에 입력 제한을 확인했다.
- [ ] 값만 필요한 문제에서는 불필요한 인덱스를 사용하지 않았다.
- [ ] `N = 1`을 반례로 확인했다.

# 오늘의 핵심 산출물 — 인덱스 범위 실수표

아래 표를 직접 채운다.

```md
| 상황 | 내가 쓴 코드 | 문제점 | 안전한 코드 |
|---|---|---|---|
| 마지막 원소 | | | |
| 전체 순회 | | | |
| 다음 원소 접근 | | | |
| 이전 원소 접근 | | | |
| 길이 1 | | | |
```

예시:

```md
| 상황 | 내가 쓴 코드 | 문제점 | 안전한 코드 |
|---|---|---|---|
| 마지막 원소 | numbers[n] | 인덱스 범위 초과 | numbers[n - 1] |
```

---

# 인덱스 핵심 공식

```text
길이 = N
첫 인덱스 = 0
마지막 인덱스 = N - 1
전체 인덱스 = 0 부터 N - 1
```

다음 원소를 함께 본다면:

```text
i 와 i + 1 사용
→ i는 0부터 N - 2까지
```

이전 원소를 함께 본다면:

```text
i - 1 과 i 사용
→ i는 1부터 N - 1까지
```

# 오늘 외울 템플릿 여부

## 값 순회

```python
for value in numbers:
    print(value)
```

## 인덱스 순회

```python
for i in range(len(numbers)):
    print(i, numbers[i])
```

## 합계

```python
total = 0

for value in numbers:
    total += value
```

## 최댓값

```python
max_value = numbers[0]

for value in numbers:
    if value > max_value:
        max_value = value
```

## 최솟값

```python
min_value = numbers[0]

for value in numbers:
    if value < min_value:
        min_value = value
```

오늘은 코드 모양을 외우기보다 다음을 설명할 수 있어야 한다.

```text
왜 초기값이 첫 원소인가?
왜 전체 순회가 O(N)인가?
왜 마지막 인덱스가 N - 1인가?
```

# 오늘의 시간복잡도

| 작업 | 시간복잡도 | 이유 |
|---|---:|---|
| 특정 인덱스 접근 | `O(1)` | 위치를 바로 알고 있음 |
| 전체 순회 | `O(N)` | N개를 한 번 확인 |
| 합계 계산 | `O(N)` | 각 값을 한 번 더함 |
| 최소값 계산 | `O(N)` | 각 값을 한 번 비교 |
| 최대값 계산 | `O(N)` | 각 값을 한 번 비교 |
| 두 번 순회 | `O(N)` | `O(2N)`에서 상수 생략 |

# 오늘의 핵심 반례

## 반례 1 — 원소 한 개

```text
N = 1
```

첫 값과 마지막 값이 같다.

## 반례 2 — 음수만 존재

최댓값 초기값을 0으로 두면 틀릴 수 있다.

## 반례 3 — 모두 같은 값

최소와 최대가 같은 값이어야 한다.

## 반례 4 — 정답이 첫 번째

최댓값 또는 최솟값이 첫 원소인 경우를 테스트한다.

## 반례 5 — 정답이 마지막

최댓값 또는 최솟값이 마지막 원소인 경우를 테스트한다.

## 반례 6 — 이웃 원소 문제

N의 최소값이 2인 문제에서 `i + 1` 범위를 확인한다.
