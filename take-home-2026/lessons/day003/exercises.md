# Day 3 Exercises — Must / Should / Could + Timeboxing

정답은 포함하지 않는다.

---

## 초급 5문제

### 1
Must와 Could의 차이를 한 문장으로 설명하라.

### 2
과제 원문에 다음 문장이 있다.

```text
시간이 남으면 예약 취소 기능도 추가해 주세요.
```

예약 취소의 가장 자연스러운 우선순위를 고르고 이유를 적어라.

### 3
4시간 과제에서 README 시간을 미리 배정해야 하는 이유를 두 가지 적어라.

### 4
`Won't`는 “절대로 구현하지 않음”과 같은 뜻인가? 아니라면 정확한 뜻을 설명하라.

### 5
Timeboxing이 한 작업의 완성도를 낮추기 위한 기법인지, 전체 제출 성공률을 높이기 위한 기법인지 설명하라.

---

## 중급 5문제

### 6
다음 180분 계획을 검토하라.

```text
요구사항 10분
구현 135분
테스트 15분
README 10분
리뷰 10분
```

합계가 맞는지 확인하고, 어떤 위험이 있는지 최소 두 가지 적어라.

### 7
다음 항목을 Must / Should / Could / Won't로 분류하라.

```text
- 게시글 생성
- 게시글 목록 조회
- README 실행 방법
- 원문에 optional로 적힌 검색
- 원문에 없는 관리자 통계 페이지
- 원문에 없는 소셜 로그인
```

각 항목의 이유를 한 줄씩 적어라.

### 8
핵심 테스트가 하나도 없는 상태에서 Optional UI 개선을 시작하려는 상황이다. 사용할 Stop Rule을 작성하라.

### 9
4시간 과제에서 핵심 기능 하나가 예상보다 30분 늦어졌다. 기능/테스트/README/리뷰 중 무엇을 어떻게 조정할지 Cut Order를 작성하라.

### 10
동료가 “8시간이나 있으니 Redis를 넣으면 기술적으로 좋아 보일 것”이라고 제안했다. 요구사항, 시간, 위험, Evidence 관점에서 답하라.

## 고급 5문제

### 11
4시간 과제 시작 2시간 후 상태가 다음과 같다.

```text
완료: 예약 조회, 예약 생성
미완료: 중복 방지, 과거 예약 방지, validation, 핵심 test, README, self review
```

남은 120분을 분 단위로 재설계하라. 선택한 순서의 이유도 적어라.

### 12
Optional 예약 취소를 40분으로 예상했지만 90분째 끝나지 않았다. 계속할지 중단할지 판단할 기준을 최소 네 가지 적고 결론을 내려라.

### 13
면접관이 묻는다.

```text
시간이 남았는데 왜 기능을 더 넣지 않았나요?
```

60초 답변을 작성하라. 다음 단어를 반드시 포함한다.

```text
원문
Core
Test
README
Known Limitation
```

### 14
Must 기능 하나가 기술적으로 어렵고 4시간 안에 완료 가능성이 낮다. 요구사항을 몰래 바꾸지 않으면서 취할 대응 전략을 단계별로 작성하라.

### 15
24시간 과제의 마지막 3시간이 남았다. 다음 네 항목에 시간을 배분하고 이유를 적어라.

```text
- 새 보너스 기능
- 추가 테스트
- README/Trade-off 정리
- Self Review
```

최종 합계는 180분이어야 한다.
