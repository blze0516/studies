# AI_POLICY.md

## 1. 가장 먼저 확인할 것

실제 회사 과제에서는 이 파일보다 **해당 회차 시험 규정**이 우선한다.

확인 질문:

- AI 사용 허용 여부
- 허용되는 AI/IDE 범위
- 인터넷 검색 허용 여부
- 외부 문서 사용 허용 여부
- AI 사용 기록 제출 여부
- 코드/대화 로그가 평가자에게 보이는지
- 공개 repository/fork 제한 여부

## 2. 평가 Mode

### Mode A — No AI

AI 생성, AI 검색, autocomplete 등이 금지되거나 엄격히 제한된 평가. 허용 범위 밖 도구를 사용하지 않는다.

### Mode B — Guarded AI

문서 검색, 설명, 제한된 autocomplete 등 일부 기능만 허용될 수 있다. 규정에 적힌 범위만 사용한다.

### Mode C — AI-Assisted / Agentic

AI 활용 자체가 평가 일부일 수 있다. 그래도 책임은 후보자에게 있다.

```text
내가 요구사항을 읽음
→ 내가 계획을 만듦
→ 작은 task로 AI에 요청
→ git diff 확인
→ 코드 직접 읽기
→ test
→ 공식 문서/실행 결과 검증
→ 채택/거절/수정 기록
→ AI 없이 설명
```

## 3. 이 98일 과정의 기본 학습 정책

- 학습 중 AI는 사용할 수 있다.
- 단, **Blind First Pass**를 우선한다. 먼저 내가 문제를 읽고 10~20분 생각한다.
- AI에게 완성 답안을 통째로 요청하기보다 요구사항 누락 검토, 설계 대안, 테스트 아이디어, diff review처럼 검증 가능한 역할을 준다.
- 기업 공개 과제 Day에서는 해당 repository/공고의 AI 정책이 최우선이다.

## 4. AI 결과를 채택하기 전 체크

- [ ] 요구사항과 맞는가?
- [ ] 존재하는 package/API인가?
- [ ] 현재 `VERSION_LOCK.md`와 호환되는가?
- [ ] 불필요한 dependency를 추가하지 않았는가?
- [ ] 보안상 위험한 코드가 없는가?
- [ ] 핵심 로직을 내가 줄 단위로 설명할 수 있는가?
- [ ] 테스트로 검증했는가?
- [ ] diff에 요구사항 밖 변경이 없는가?

## 5. Day 1 학습 Mode

Day 1은 실제 채용 시험이 아니라 학습일이므로 **Mode C**를 사용한다. 단, 공개 과제 3개를 읽을 때는 먼저 AI 없이 평가 신호를 직접 적고, 그 다음 AI를 “누락 검토자”로만 활용한다.
